3Plans

Predefined plans are shared and read-only; custom plans belong to this account. The API checks ownership and scope on every change.

Create a custom plan

POST /v1/plans

Update a custom plan

PATCH /v1/plans/{planId} · only filled fields are sent. Predefined plans are read-only (the API answers 409).

Assign the account plan

PUT /v1/account/plan · a USER plan is refused by the API (409).

4Users

Users of this account. New users start on the Basic plan.

Create a user

POST /v1/users · the new user becomes active.

Read one user

GET /v1/users/{userId} · try an ID from another account: same 404 as an unknown ID.

Assign the active user's plan

PUT /v1/users/{userId}/plan · an ACCOUNT plan is refused by the API (409).

7About this demo

This interface is an external demonstration client. All validation, authentication, authorization, idempotency and quota enforcement remain in the backend service.

  • The page talks only to the local demo server, which forwards /health/live, /health/ready and /v1/* to the API unchanged.
  • The API key lives only in this page's memory: no storage, cookies or URLs. Refreshing the page forgets it.
  • The demo creates accounts, plans, users and decisions; it never deletes data.
