# Requirements traceability

Each requirement of the project specification, with where it is implemented, what proves it and
where it is documented.

## Source

- **Specification:** the "Final Project: Usage Metering and Quota Service" section of the course
  plan, from Overview to Deliverables and Project Submission.
- **Version used:** the text read on 2026-10-11 and checked again on 2026-10-16; both copies were
  identical (1,425 words).
- **Interpretations:** where the specification leaves behavior open, the choices are listed with
  their reasoning in the README's [Product assumptions](../README.md#product-assumptions).

**Evidence used below:**

- **Tests** are in `tests/`. Integration tests run against real PostgreSQL.
- **CI** is the GitHub Actions workflow
  [.github/workflows/ci.yml](../.github/workflows/ci.yml), on every pull request and push to
  `main`. Its jobs are "Quality gates and tests" (CI-Q) and "Container image and Compose stack"
  (CI-C).
- **Perf** is the full benchmark run 38751721971 ([performance.md](performance.md)).

**Status values:** **Complete** means implementation, tests, CI evidence and documentation agree.
**Pending (human)** means the item is outside the repository.

## Optional, conditional and out of scope

| Item                                                                                                                   | Classification               | Reason                                                                                                                                                        |
| ---------------------------------------------------------------------------------------------------------------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Additional rule types ("explain how any additional rules interact")                                                    | Conditional, not triggered   | No rule types beyond the two required ones were added ([assumption 13](../README.md#product-assumptions)).                                                    |
| Combined history index `(account_id, user_id, month, seq)`                                                             | Rejected by measurement      | Median p95 2.359 ms and 4 rows removed, against the pre-registered thresholds of 50 ms or 2,000 rows ([performance.md](performance.md#decision)).             |
| S3 sensitivity benchmark                                                                                               | Conditional, not run         | S3 was informative only and never decides; the binding rule excluded it once the history criterion failed.                                                    |
| Operational metrics (for example a Prometheus endpoint)                                                                | Optional, not implemented    | The specification does not ask for metrics; structured JSON logs are implemented.                                                                             |
| `503` on connection-acquire timeout; per-account concurrency limit; single-round-trip critical section                 | Optional, deferred           | None is required; the limiter would first need a mixed-tenant benchmark showing interference ([architecture.md](architecture.md#deferred-optional-features)). |
| Database-level mutation experiments for the newest tests                                                               | Optional, not run            | Not a specification requirement; the tests passed in five consecutive CI attempts.                                                                            |
| Billing, payments, refunds, several resource types, end-user login, role-based permissions, distributed infrastructure | Out of scope (specification) | Listed as outside the required scope; none is implemented.                                                                                                    |
